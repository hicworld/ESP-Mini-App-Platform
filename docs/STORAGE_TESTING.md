# 应用存储故障验证

## 运行

```powershell
python tools/test_storage_host.py
# 或运行包括该套件在内的完整主机测试
./Run.ps1 Test
```

要求已安装项目固定的 WASI SDK 和 Node.js。测试编译原始 `firmware/main/app_manager.c`，通过 WASI 在一次性临时目录中读写真实文件，退出后清理该目录。不会连接开发板或访问它的存储。

## 37 项存储与下载事务覆盖

其中 30 项直接执行应用管理器与 NAND 迁移代码：

- 更新失败：文件打开、短写、flush、fsync、close、回读为另一个有效包、NVS set、提交失败且保留旧记录、提交失败但新记录已经持久化、剩余空间不足、不合理空间统计、SPIFFS 统计失败。
- 卸载失败：NVS set 失败，以及 commit 失败的旧记录/新记录两种持久结果。检查失败后文件保留，重新加载后可再次安装。
- Registry 损坏：错误 schema、超过容量、未终止 ID、非法路径、重复 ID、记录大小不符、未知权限位、超限 WASM 大小、非法版本、空名称。检查拒绝加载、禁止继续修改、禁止自动播种内置应用，不覆盖原始记录。
- 正常更新、卸载、空列表重载；运行中、存储不可用、无效包的拒绝。
- 应用数据清除：正常清除；不存在、无 `storage` 权限、应用运行中和后端失败的拒绝。
- NAND 迁移：旧 NOR 活动包复制后 Registry 逻辑路径保持兼容、两份文件并存、删除测试环境中的 NOR 副本后仍可从 NAND 读取并在重新初始化后恢复；无效 NAND 副本会由已验签的 NOR 包替换。

另有 7 项直接执行生产 `download_cache.c`：正常提交、加载与清理；启动时清理中断残留；文件打开失败、短写/满盘、flush、fsync、close 和原子改名失败。所有失败路径都要求 `.part` 与 `.ready` 不残留。

写入失败后仍应读取旧版本；NVS 提交结果不确定时暂停修改，重新初始化后依据持久记录读取旧版或新版。恢复后应可再次成功更新。回读包必须与输入包逐字节一致，再完成验签，最后提交 Registry。

## 测试边界

NVS、空间统计和包验签使用受控替身。模拟重启仅重新执行 `apps_init()`、丢弃未提交 NVS 状态；测试没有模拟 Flash 扇区撕裂、SPIFFS 掉电一致性或真实 NVS 的硬件行为，也没有在主机套件中验证密码学。

真实包签名/篡改拒绝由 Python 包测试和板上验收覆盖。0.3.0 实机已覆盖 COS 正常下载、404 失败清理和软件重启恢复；真实拔电、传输中断与物理满盘仍需单独验收，不能由本套件的 37/37 结果代替。

## 7 项应用数据命名空间覆盖

`python tools/test_app_data_host.py` 直接编译 `firmware/main/app_data.c`，验证非法参数、同一 ID 的稳定映射、不同 ID 的隔离、哈希冲突拒绝、清除后重新创建、空命名空间重复清除和 NVS commit 失败传播。板载 `selftest` 还会在真实 NVS 中写入、清除、重新打开并确认键已不存在。

0.2.6 测试先在修复前复现 5 项失败：回读成其他有效包，以及 Registry 中未知权限、异常 WASM 大小、非法版本、空名称未被拒绝。0.2.7 加入数据清除入口和独立命名空间套件后，应用管理器 28/28、应用数据 7/7 通过。0.2.9 把事务后端切换为 NAND 优先并增加两项兼容迁移测试。0.3.0 增加 7 项下载缓存事务测试，当前存储套件为 37/37，应用数据仍为 7/7。

验签代码迁入 `app_verify.c`，ID/版本规则由 `app_validation.h` 共享；存储测试直接编译生产事务代码，以便后续修改继续验证同一套故障语义。
